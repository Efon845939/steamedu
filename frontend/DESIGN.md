# STEAM Hub design system

STEAM Hub is a misconception lab. Every wrong idea is a specimen a student catches,
labels and files. It is not a failure. The UI is flat, type does the work, each age
theme has exactly one accent, and motion only answers what the person did.

This file is the contract for anyone changing the frontend. The visual proposal it came
from is the "STEAM Hub theme proposal" canvas.

## Themes

The theme is fixed by the account and never user-selectable. `html[data-age]` is set
from `user.age_group` (students), `teacher` (teachers) or `16-18` (logged out) by
`src/lib/theme.js`, and before first paint by `public/index.html`.

| `data-age` | Name | Accent | Display / body type | Marks |
|---|---|---|---|---|
| `13-15` | Field notebook | phenolphthalein pink fill, dark text on it | Archivo 125 wide 700/800, Atkinson Hyperlegible Next | trace 3px, wavy 2px, radius 6/10/14, snappy spring |
| `16-18` | Engineering pad (also the brand and landing theme) | ink blue | Archivo 112 wide 700, Atkinson | trace 2px, wavy 1.5px, radius 6/8/10 |
| `18+` | Journal and slate | verdigris | Source Serif 4 600, Atkinson | trace 1px, wavy 1px, radius 4/6/8, compact |
| `teacher` | Ledger | slate blue, low saturation | Archivo 600, IBM Plex Sans (tabular figures) | radius 4/6/8, compact, data first |

Where gamification lives, by age: points and streak sit in the header at 13-15, in the
dashboard side column at 16-18, and only in the profile at 18+. Teachers never see them
as decoration.

What people can change (Display panel in the header): appearance (light, dark,
system), text size (S, M, L), motion (full, reduced, off, default follows the device),
density (comfortable, compact) and lite mode. Nothing else.

## Tokens

Colours are CSS variables generated by `scripts/theme-tokens.py` into
`src/theme/tokens.css` (it also checks WCAG contrast). Type, radius, shadows and motion
are in `src/index.css`. Use Tailwind classes, never hex values.

**Colour classes**

- Page and surfaces: `bg-bg` (page), `bg-surface` (panels, inputs), `bg-neutral-tint` (quiet fill, hover)
- Text: `text-ink`, `text-ink-muted`
- Rules: `border-rule` (hairline), `border-rule-strong` (inputs, checkboxes, empty cells, at least 3:1)
- Accent: `bg-brand text-on-brand` (the one primary action), `text-brand-ink` (links, selected labels, trace), `bg-brand-tint` (selected state)
- Status, each with `-tint` and `-rule`: `success` (Holds), `warning` (Unsure, Needs review), `danger` (Breaks here, Not quite, Returned), `info` (Given, Hint, New; never a filled button)
- Heatmap ramp: `bg-ramp-0` ... `bg-ramp-5` with `text-ramp-ink-0` ... `text-ramp-ink-5`
- Old palette names (`gray-*`, `emerald-*`, `amber-*` ...) still resolve onto the theme, but do not write them in new code.

**Type classes** (the sizes follow the theme): `t-display` (landing hero only), `t-h1`,
`t-h2`, `t-h3`, `t-lead`, `t-body`, `t-cap` (muted caption), `t-num` (score, points,
timer, rank: tabular figures in the theme's numeral face), `tnum` (tabular figures
only). `text-xs` ... `text-5xl` also map to the theme scale; the smallest text is 14px at
13-15 and 13px elsewhere.

**Shape**: `rounded-sm` (chips, inputs), `rounded-md` (buttons, answer rows),
`rounded-xl` (the raised strip, dialogs), `rounded-label` (4px specimen labels),
`rounded-full` only for avatars. Graph paper is square.

**Elevation**: content sits on the page separated by hairlines and whitespace.
`surface-raised` (or `shadow-raised`) is for the ONE raised element per screen (the Next
up strip, a side panel). `shadow-float` is for popovers, dialogs and toasts. Dark mode
drops shadows.

## The three marks

`src/components/lab` has them. Each screen has exactly one focal mark; the others are
absent or quiet.

- `SpecimenLabel name="Impetus" code?` a misconception, filed. Names come from
  `misconceptionName(tag, lang)` in `src/lib/misconceptions.js`.
- `CorrectionMark` a wavy danger underline on the first wrong step (`draw` reveals it).
  Accent links are straight, so the wavy line never reads as a link.
- `Trace levels={['holds','breaks','unsure']} draw?` a flat line that steps down at a
  wrong idea and back up when it is fixed.
- `GraphPaper` only inside real work areas: a question diagram, a worked solution, a
  scenario preview.
- `StatusWord status="holds|unsure|breaks|wrong|given|hint|approved|review|returned|changes|new"`
  colour plus a fixed lucide glyph plus a word. Colour is never the only signal.
- `BrandMark`, `Wordmark`: the step trace with one kink.

## Motion

- One orchestrated moment per screen; everything else only answers input.
- Exit faster than enter. Interactive motion uses the theme spring.
- Never block input; the Next and Check buttons stay live; final values (score,
  points, rank) are in the DOM and in `aria-live` from the first frame. Count-ups are a
  visual layer only, and never in reduced mode.
- Page-load entrances are CSS: `animate-rise`, `animate-fade`, `animate-pin` (they
  follow the theme's duration, travel and spring, and the reduced/off settings).
- For interaction-driven motion (answer reveal, arena verdict, side panel), wrap the
  page in `<MotionScope>` from `src/lib/motion.js` and use `import * as m from
  'motion/react-m'`. Read timings with `useMotion()` from `src/lib/motion-tokens.js`
  (`mo.full`, `mo.spring`, `mo.enter`, `mo.stagger`, `mo.rise`, `mo.pin`).
- Only lazy route pages may import `src/lib/motion.js`. App, Navbar and HomePage must
  not (it keeps motion out of the main bundle for slow connections).
- Reduced: opacity only, 120ms. Off and lite: nothing moves. Both are handled globally;
  final states must be the no-animation state.

The moments: landing, the arena sample verdict on tap. Student dashboard, a fixed
idea's trace steps up once. Diagnostic quiz, the answer reveal (Check becomes Next in
place in a sticky bar). Results, the trace draws. Debug Arena, the verdict (steps tick
"Holds" top-down 60ms apart, stop at the wrong step, the correction mark springs in;
600ms cap). Badge unlock, an inline "specimen pinned" line, never a modal. Teacher
X-ray, columns fade in once per session.

## Rules

- No raw palette or hex colours, no gradients, no glow, no glass/blur, no `bg-white`.
- No emoji anywhere (icons are lucide, `currentColor`, never inside coloured circles).
- No em dashes in UI copy. No exclamation marks in success copy ("Correct. You kept
  force and motion apart."). Sentence case. No tracked all-caps eyebrows.
- No stacks of identical cards: lists are rows with hairlines. No KPI tile grids for
  teachers; a summary is one sentence of numbers.
- Subjects get text labels, never S/T/E/A/M letter circles.
- 44px minimum for touch targets (`h-11`), 24px minimum for anything else. Icon-only
  buttons need `aria-label`.
- Use real `button`, `a`, `label` + input. Keep every existing `data-testid`.
- Turkish content gets `lang="tr"`. Sort Turkish names with `Intl.Collator('tr')`.
- Pages must not render their own `<main>` (App provides `<main id="main">`).
- Lite mode (`useLiteMode().lite`): skip photos and anything heavy in JS, not with CSS.
